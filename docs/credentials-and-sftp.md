# 凭据升级与 SFTP 文件工作台

## 凭据存储与迁移

Orbit 将随机生成的 256 位 AES 密钥保存到 macOS 登录 Keychain，service 为 `com.orbit.terminal.credentials.v2`、account 为 `master-key`。服务器密码、私钥内容、私钥口令、凭据组和数据库密码使用新的 `ORB2:` 格式加密；AI API Key 也加密后写入偏好设置。内存中的连接信息仍按需解密使用。

首次启动会验证 Keychain 密钥，迁移旧明文和 ORB1 凭据。数据库中的全部凭据迁移在一个 SQLite 事务中完成，并验证新密文可解密；任何错误都会回滚全部凭据改动。已迁移的字段不重复加密。AI 配置单独处理，仅在加解密与序列化均成功后替换旧配置。

- Keychain 锁定或拒绝访问：解锁登录钥匙串并允许 Orbit 访问，然后重启应用重试。不会回退到明文存储。
- 已迁移数据库的密钥丢失：不会创建替代密钥覆盖旧数据。恢复原 Keychain 条目或匹配的整套备份，再重试；只有数据库文件不能恢复 ORB2 凭据。
- ORB1 解密失败：保留原值并停止迁移。旧格式依赖原 Mac 的 hostname，须在原环境恢复或使用原始备份；不会把无法解密的密文当作密码继续使用。
- 密文损坏：保留原数据，恢复有效备份后重试。不要为了消除错误删除数据库或 Keychain 条目。
- 成功迁移后不支持用旧版 Orbit 读写新密文。需要回退版本时，应恢复升级前数据库与相应设置备份。
- 原有“导出配置”仍是明确提示的明文导出功能；Keychain 本地加密不改变该功能，导出文件需要单独妥善保管。

## SFTP 行为

主页面、抽屉和快捷浮层共用队列实现。每个任务独立标识进度，按队列顺序执行；关闭浮层不会丢弃传输，关闭对应标签或删除服务器会请求取消。失败或取消的任务可手动重试，重试从头开始，不是断点续传。

上传与下载先写入目标目录的 `.orbit-transfer-<随机ID>.part` 文件。只有完整复制成功且未取消时才提交；本地文件先同步落盘。目标已存在时，任务停在“等待覆盖确认”，确认具体目标后重新执行。进度到 100% 不代表已完成，只有最终提交成功才显示完成。

远程覆盖使用 `posix-rename@openssh.com` 原子重命名扩展；不支持时明确失败，绝不先删除目标再重命名。本地覆盖使用同目录 rename；不覆盖时用排他创建语义，防止检查后出现的新文件被覆盖。普通文件之外的目标不允许覆盖。替换已有文件时保留其权限位；新文件使用 0600。

取消会在数据块之间检查；正在等待网络 I/O 时可能需要等待超时。取消进入“正在取消”后，收到后端确认才显示“已取消”。连接中断时尽力删除临时文件；远端不可达时可能留下 `.part` 文件，原目标不会被部分内容截断。提交阶段连接丢失时，应刷新核对最终文件，再决定是否重试。

文件列表通过 SFTP 协议获取，支持名称筛选、隐藏文件开关、路径输入、上传多选、拖拽上传、下载、重命名、删除、新建目录和已有文本编辑入口。

## 设计与验证

[视觉稿](design/sftp-workspace-concept.png) 是生成的设计参考，不是运行截图。实现采用系统颜色，兼容浅色/深色外观；完整页面保留元数据列，紧凑浮层只显示名称和大小。传输任务的状态、目标路径和后续操作放在一起。

```bash
cargo test --manifest-path orbit-rs/Cargo.toml --lib
cargo test --manifest-path orbit-rs/Cargo.toml host_key::sshd_tests -- --ignored
cargo test --manifest-path orbit-rs/Cargo.toml native_keychain_roundtrip -- --ignored
```

第二条命令创建临时本机 SSH 服务和测试密钥，验证直连、跳板机及 SFTP 上传、下载、覆盖、取消与临时文件清理。第三条命令只创建并删除唯一命名的测试 Keychain 条目，不修改已有条目。
